### 指摘
- [C-640] 種別: 実装 / 深刻度: high
  - 指摘: 言い換えの疑いの記載には、その日の原文にある分からない略語（言い換えのない記載の名前に出ないもの）がすべて付く。その記載と関係のない語でも付く。
  - 破綻シナリオ: 原文は「S: ADL低下、NRS3 / O: 在宅患者訪問診療。ＥＣＧ１２。/ P: 在宅酸素療法の指導。」。LLM は written「在宅酸素療法指導管理」、quote「在宅酸素療法の指導」を返す。tsx で markDay に通すと、この行為に `abbrev: ["ADL","NRS3"]` が付き、lookup は空になった。医師には「この記載の『ADL』は何を指しますか」が届き、引用は「在宅酸素療法の指導」だけになる（quoteOf は ADL を含む文を見つけられず、引用全体を使う）。医師が「日常生活動作」と記入すると、doctorWordsAt によってその語が在宅酸素の行為の候補を引く lookup になる。round-97 C-632 で外したはずの「無関係な語の問いと、無関係な lookup」が、その日の全文に広がって戻っている。言い換えの疑いの記載が 1 日に複数あると、全部が同じ ADL の問いに束ねられる。事実も同じ扱いになり、処方 value「利尿薬」（quote「フロセミド」）と急性増悪 value「あり」（quote「急変」）にも `["ADL","NRS3"]` が付いた。病名の記載ではない事実は医師には届かないが、画面に「略語あり」の札が出る（app/chart/page.tsx 268 行）
  - 提案: 言い換えの疑いの記載に付ける語は、その記載の引用（abbrevMarks(quote)）の中の分からない語に限る。処方・急性増悪・不安・不眠の薬は、プロンプトの指示で value が言い換えになる種類なので、言い換えの判定から外す（病名の記載と行為・子だけに当てる）。

- [C-641] 種別: 設計 / 深刻度: high
  - 指摘: 「書かれた名前が引用に含まれない」を、NFKC と空白の除去だけで判定している。このため正しい取り出しも言い換えの疑いになり、略語でもない名前そのものが医師への問いになる。自動選択も止まる。

    全角と半角（ＥＣＧ１２・０．５ｇ・ﾌﾛｾﾐﾄﾞ）と、「心電図／心電図をとった」は通る。その日の原文に分からない略語がないと、問いの語は書かれた名前そのものになる。医師には「この記載の『在宅酸素療法指導管理』は何を指しますか」という、答えようのない問いが届く。さらに written「酸素ボンベ加算」・quote「酸素ボンベ使用」では、問いの文が「この記載の『酸素ボンベ加算』は何を指しますか」になった。abbrevQueryErrors と同じ validateQuery が「④点数・金額・請求に触れている」を返す（tsx で確認）。医師確認の 7 要件④に反する。schemas/doctor.ts で token の正規表現を外したので、POST でもこの語を受け取る。訪問の行為は毎回のカルテにあるので、問いが訪問の回数だけ増え得る。これは実務第一の方針に反する

- [C-642] 種別: 実装 / 深刻度: mid
  - 指摘: 言い換えかどうかを「written が quote に含まれるか」だけで決めている。quote は「カルテのどこかにある文字」であればよい。このため LLM が、言い換えた語と同じ文字をカルテの別の場所から引用に取れば、今も印が付かない。
  - 破綻シナリオ: 原文は「O: ECG12施行。前回の心電図と著変なし」。LLM は ECG12 の行為を written「心電図」、quote「前回の心電図」として返す。validateActs は引用がカルテにあることしか見ないので通る。tsx で markDay に通すと、abbrev は付かず、lookup「心電図（１２誘導）」もそのまま残った。印のまとめには ECG12 が出るのに、聞く件数は 0 になり、名称の完全一致か前に選んだ対応で自動選択される。展開した語が同じカルテの別の場所に書かれている形（前回との比較・既往・指示の文）は、在宅のカルテでは珍しくない
