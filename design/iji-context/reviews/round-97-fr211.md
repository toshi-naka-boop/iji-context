### 指摘
- [C-630] 種別: 実装 / 深刻度: high
  - 指摘: 確かめる画面の「候補を引き直す」は引用を渡さずに `actCandidates` を呼ぶ。このため、X-490 で止めた自動選択が 1 クリックで戻る。
  - 破綻シナリオ: 原文「ECG12施行」から LLM が written「心電図」、quote「ECG12施行」を返す。取り出した直後は引用の語で印が付き、lookup は空、initial は null になる（直しが効いている）。ところが確かめる画面（acts-review.tsx の 165 行・177 行の MatchPicker は `at` を渡さない）で「候補を引き直す」を押すと、`actCandidates(key, ym, "心電図", [])` が走る。ここで `markedIn(...)(key, written)` は quote を既定の "" として判定するので、印がない扱いになる。tsx で `itemMarks("心電図", "", vocab, true)` が `[]` を返すことを確認した。結果は `matchItem(..., aliasOf("心電図"))` に進み、名称の完全一致か前に選んだ対応が initial になる。`onChange({ m, sel: m.initial })` で「当てた」がそのまま選ばれ、保存すると match が付くので、医師への問いから消える。
  - 提案: 候補の API に quote（または行為の位置）を渡し、`markedIn(key, written, quote)` で判定する。もう一つの方法は、印のある行（r.abbrev）では画面側で `sel: null` に固定する。
- [C-631] 種別: 実装 / 深刻度: mid
  - 指摘: 言い換えを見抜けるかは、LLM が引用に原文の略語を残すかどうかに頼っている。引用から略語を外されると、今も印が付かない。
  - 破綻シナリオ: 原文「AF 継続。ECG12 施行」から、LLM が written「心電図」・quote「施行」、病名の記載 value「心房細動」・quote「継続」を返す。validateActs と validateFacts は「引用がカルテのどこかにあるか」しか見ないので、どちらも通る。tsx で markActs と markFacts の結果に abbrev が付かないことを確認した。印のまとめ（全文の marks）には AF が出る。それでも asked は 0 になり、医師への問いは作られず、lookup と自動選択がそのまま生きる。取り出しの指示では「書かれた名前のまま written に出す」と決めているのに、written が引用の中にあるかは検査していない。
  - 提案: 決まった規則を 1 つ足す。normName(written) が normName(quote) に含まれない行為・子・病名の記載は「言い換え」とみなし、lookup を空にして自動選択しない。印も付けるなら、引用の前後の語を対象にするか、少なくとも聞く対象にする。
- [C-632] 種別: 実装 / 深刻度: mid
  - 指摘: 引用全体の印を記載に足すため、引用に入り込んだ別の略語まで、その記載の印になる。もともと名称の完全一致で自動選択できた行為が、医師への問いに回ってしまう。
  - 破綻シナリオ: LLM が ECG12（基本マスターの名称にある）の行為に quote「AF継続、ECG12施行」を付ける。tsx で `abbrev: ["AF"]` が付き、lookup が空になることを確認した。この結果、ECG12 は自動では当てられなくなり、医師には「AF」の問いがこの心電図の行為の引用付きで届く。医師が「心房細動」と記入すると、その語が心電図の行為の候補を引く lookup になり、医科診療行為の表から関係のない候補が出る。引用は「短い部分」としか縛っていないので、1 行まるごと写す出力はよくある。そのたびに医師の負担と事務の手戻りが増え、実務第一の方針に反する。
