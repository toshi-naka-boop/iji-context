# モバカル（movacal.net）の API で読める項目の問い合わせ（2026-11-23）

最初のクリニックの電子カルテはモバカル、API で受け取る想定（利用者の判断 2026-11-23）。公開の API 仕様は見つからない（Web 検索。提供元への問い合わせが要る）。厚労省「電子カルテ及びレセプトコンピュータ標準仕様書（基本要件）第1.0版」（令和8年3月31日。中小病院向け。https://www.mhlw.go.jp/content/10800000/001683680.pdf）の 2.2.4（電子カルテ－業務効率化サービスの API）は、必須・推奨とも「次版以降において設定予定」で、標準から項目は決められない。

外部連携の実績（公開情報）：今日の治療薬WEB との連携（https://kyodonewsprwire.jp/release/202509094860）、在宅医療支援システムからの自動同期（https://www.hokkaido-np.co.jp/article/1322458/）。

## なぜ要るか
今のレセメンはカルテを文字（S・O・A・P・処方の名前）としか受け取らない（src/connect/types.ts の ConnectorChart）。調剤料・処方料・処方箋料・患家診療時間加算・材料加算は、実物の電子カルテでは構造化データ（オーダー・時刻・機器）にあるはずで、そこから決まった規則で出すのが筋（AI に推し量らせない）。

## 提供元に聞く項目
1. 処方：薬のコード（レセ電コード／YJ コード／独自）、剤形、用量・日数、院内か院外か
2. 注射・処置：行為のコード（医事のレセ電コードと対応するか）、使った薬・材料とその数
3. 訪問の記録：訪問日、診療の開始・終了の時刻、訪問診療か往診か
4. 在宅療養：指導管理の種類、使っている機器（酸素濃縮装置・酸素ボンベ・液化酸素・輸液ポンプ等）とその開始日
5. 文章：S・O・A・P の本文
6. 患者の情報：保険・公費、要介護度、居住の場所（施設・同一建物か）
7. 取り方：API の形式（REST・FHIR 等）、認証、取れる単位（患者・日・期間）、試験用の環境、利用の条件・費用、個人情報の扱い（委託・契約）
