spec.md FR-211：略語の医師への確認。振り分けは「直接」（設計ループなし。ルールエンジンに触れない。医師確認〔F1〕と整形・取り出しの流れが変わる）。入力は spec FR-211・FR-30・FR-174 と reviews/fable-consult-fr211.md。進める順は FR-203 のとおり I-2 の後（ブランチ feat/fr211。feat/integration から）。

## 何を作るか
1. **分からない略語の決め方**（src/chart/abbrev.ts 新設。決まった規則だけ。LLM の確信度は使わない）
   - 語の切り方：原文を NFKC にし、`/[A-Za-z]+[0-9]*/g` で切った語のうち 2 文字以上（ECG12・FT4・SpO2・T3 は 1 語、ID70mg は ID70 と mg）。大文字・小文字は区別する（Af と AF は別の語。docs/sources/report-A.md §22 の多義の例）。
   - 分かる語：(a) 診療年月の 1 枚の基本マスター 4 本（医科診療行為・医薬品・特定器材・傷病名）の名称を同じ切り方で切った語の集合にある語（IgE・AST など）、(b) 固定の一覧にある語。どちらでもない語に印を付ける。
   - 固定の一覧は **config/abbrev-known.json** に置く（単位・バイタルは制度・点数の値ではなく設計の値なので EM ではなく config。CLAUDE.md「唯一の採用値」の対象外）。中身は利用者の承認つきで、ファイルに承認日を書く（確かめる点 2）。
   - 聞くのは効く所だけ：行為（with の子を含む）の written に印の語があり、引く表に名称の完全一致がなく、当てていない（match なし・たたんでいない）とき。病名の記載は、value に印の語があり傷病名マスターに完全一致がないとき（事実を残すのは訪問カルテだけ。貼ったカルテ〔記録〕は今も事実を使わないので、行為だけを聞く）。ほかの印（S・O だけの語など）は数だけ出す。
   - マスターがない・版のない診療年月は印を付けず「マスターがないので略語は見ていません」と出す（全部を聞かない）。
2. **印の持ち方**
   - 印は保存のとき（行ったことの確かめ・事実の確定）にサーバーで付け直し、chart_notes.acts と facts の JSON に `abbrev: string[]` として持つ（画面から来た値は使わない。マスターの更新で印が動かないように保存時の値を持つ）。原文は書き換えない。
   - 答えは **APP_MIGRATIONS の 24**（I-2 までに番号が使われていれば、その時点の次の空き番号。連番の検査が止める）で 2 表を足す。どちらも追記だけ。
     - `abbrev_answers`：id・year_month・token・option（記入・記載によって違う・その他・判定不能）・free_text・answered_by・answered_at
     - `abbrev_answer_items`：answer_id・note_id・place（act・child・fact）・item_key（written と quote の指紋。位置の番号は保存し直すとずれるので使わない）
   - 患者 id・氏名は持たない（note_id から請求に戻る）。カルテを消すと、その note_id の items を消し、items のなくなった答えも消す（FR-168 の全表走査に足す）。
3. **lookup と aliases の止め方**（1 か所に寄せる）
   - 取り出した直後（extractFacts の validateActs の後）に、聞く行為の lookup を空にする。保存もしない（画面の lookup の欄にも出ない）。
   - 候補を作る 3 か所（notes.ts の actsReview・actCandidates、B の当てられない行為の候補）で、聞く行為は alias を引かず、lookup は「医師の答え」だけにする（下の 5）。書かれた名前の部分一致の候補（規則）は今までどおり出す。
   - confirmActs・pickAct で、印のある written は chart_act_aliases に書かない。FR-211 の前に覚えた行があっても、印のある written では読まない（行は消さない）。
4. **医師への問いの作り方とまとめ方**（src/server/app/doctor-abbrevs.ts 新設。GET・POST /api/doctor/abbrevs。医師の役割だけ）
   - 問いは定型文 1 つ：「この記載の『{語}』は何を指しますか」。選択肢は固定で「指すものを記入する」「記載によって違う」「その他」「判定不能」（同じ大きさのボタン）。LLM に作らせない。
   - まとめ：答えの付いていない記載を（診療年月・語）で束ねて 1 問。引用は請求の番号と日付ごとに並べる（氏名は出さない）。「記載によって違う」の答えが付いた記載は、記載 1 つずつの問いに割る。
   - 答えは、答えた時点で並んでいた記載にだけ効く。答えの後に同じ月に増えた記載は新しい問いになる（医師が見ていない記載に答えを広げない）。
   - 7 要件：①引用（カルテの日付と文）②定型文で誘導しない ③「その他」「判定不能」④問い・選択肢・引用に点数・金額の語を出さない（引用は語を含む文 1 つに切り、MONEY の語は「＊＊」で伏せて「伏せた語があります」と添える）⑤定型文と選択肢を validateQuery と同じ検査に掛けるテスト ⑥答えを追記で残す ⑦最初の記載の確かめから営業日を数え、1 営業日でリマインド、3 営業日で保留の印（doctor-query の tickQueries と同じ数え方。保存せず読むときに決める）。
   - 「その他」は記述つき、「判定不能」は記述なし（FR-174 と同じ）。どちらも事実にせず、その記載は「見ていません」のまま。
5. **答えを取り出しに戻す道**（覚えない）
   - 「指すものを記入する」の答えは、その答えが効く記載の候補を作るときだけ lookup の語として使う。自動では当てない（lookup で自動に当てない今の規則のまま）。当てるのは医療事務で、当てた結果は `by: "doctor"`（医師の答えから選んだ）。
   - 答えは診療年月と記載に結び付くので、翌月の同じ語は改めて聞く（クリニックごとの表を作らない）。
   - 病名の記載は値を書き換えず、確かめる画面で「医師の答え：…」を並べるだけ。
   - B の欄：聞く行為は当てられない行為の一覧に「略語を医師に確かめ中」の札で並べ、範囲に「略語を医師に確かめ中 n 件（その行為は見ていません）」「医師が判定不能・その他と答えた略語 n 件（見ていません）」を出す（torikawasure.ts で足す。g11.ts の判定は変えない）。
6. **整形の確かめ**：formatSoap の結果で、原文の印の語が整えた欄から消えていれば `lostAbbrevs` として返し、原文にない言い回しと同じ場所に「整形で消えた略語」として出す（指示文は変えない）。
7. **画面**
   - 医師確認：「確かめてほしい項目」の中に略語の問いのカード（app/doctor/abbrev-requests.tsx）。語・診療年月・件数・引用の一覧・選択肢・記入欄。点数・金額は出さない。
   - 行ったことの確かめ（app/chart/acts-review.tsx）：印のある行為に「略語：ECG12（医師に確かめ中）」の札。候補は答えが来てから。
   - 貼った直後と B の欄（app/torikawasure.tsx）に、印の数と聞く数。

## 危ないところと守り手

- **医療事務の手間が増える**（実務第一と食い違う）：分かっている略語でも医師待ちになる。→ 固定の一覧を小さく保ちつつ、確かめる点 1 で手で探して当てる道を決める。
- **1 問で多数の患者に答えて誤りが広がる**（AF／Af／AFL、PD など多義の語）：→ 大文字・小文字を分ける、「記載によって違う」を同じ大きさで並べる、答えは並んでいた記載にだけ効く、自動で当てない。
- **引用の伏せ字で臨床指標が欠ける**：→ 伏せた事実を添える。伏せる語は MONEY の正規表現そのもの（新しい語の表を作らない）。
- **記載の同定がずれる**：保存し直しで位置が変わる。→ written と quote の指紋で結ぶ。指紋が変わった記載は新しい問い（古い答えを流用しない）をテストで縛る。

## 規則の作り直し（2026-11-25。反証 round-96〜98 と Fable の相談による。承認済み：利用者「承認します」）
言い換えの疑い（書かれた名前が引用に含まれるか）で決める規則をやめ、**語を単位**にする。
1. その日の原文から、分からない略語の語を規則で拾う（今と同じ。英字の語から名称の語と固定の一覧を除く）
2. **問いは語ごと**：同じ月・同じ語で 1 問。引用はいつも、原文のその語を含む文（記載の引用は使わない）。問いの語は英字の略語だけ（名前そのものを聞かない。token の検査は英字の形に戻す）
3. **結び付き**：記載（行為・子・病名）を語に結び付けるのは、書かれた名前・値にその語があるとき、又は引用にその語があって書かれた名前が引用に含まれないときだけ。結び付いた記載は自動選択も lookup もしない（覚えない）。結び付いた語は医師に聞く
4. **どの記載にも結び付かない語**（取り出しから漏れた語。処方の分類名などの事実にだけ出る語を含む）は、事務が先に「算定に関係なし」か「医師に聞く」を選ぶ。選ぶまで、その日のカルテは「確かめ済み」にしない（略語の確かめ待ち）
5. 言い換えの疑いだけでは医師に聞かない
6. 受け入れ条件：round-96〜98 の例（AF→心房細動・ECG12→心電図・引用を別の文にした組・ADL/NRS3・処方の分類名・「の」「料」の違い・酸素ボンベ加算）をテストで縛る

## 作り直しの補い（2026-11-25。round-99 C-650〜C-652 と Fable の相談。承認済み：利用者「承認します」）
- **規則 3 の補い（C-650）**：引用に語があって書かれた名前が引用に含まれないときは、引用を「。、・改行」で節に区切り、書かれた名前と重なる節の語だけを結ぶ。重なる節がなければ（AF→心房細動のような言い換え）今までどおり引用全体の語を結ぶ
- **規則 4 の補い（C-652）**：結び付かない語の扱いは、その月にその語が出ているカルテを一覧（各カルテのその語を含む文つき）で見せてまとめて選ばせ、保存は**カルテと語の組**にする。選んだときに並んでいたカルテにだけ効く。あとから書いた・直したカルテは選び直し。「医師に聞く」も同じ範囲
- **C-651**：確定の前に残った記載で判定し直した結果に合わせて、選ぶボタンを出し直す（実装の直し）

## 結び付けをやめる（2026-11-25 案。round-100 C-660 と Fable の相談。承認前）
字面で語と記載を結び付ける規則（作り直しの 3・補いの C-650）をやめる。
1. その日の原文に分からない略語が 1 つでもあれば、その日の記載は全部、LLM の lookup と自動選択（初期値）を止める。名称の決まった規則での候補は残し、事務が選ぶ。止めるのは事務の選択では解かない（「算定に関係なし」を選んでも止まったまま）
2. 略語は語ごとに、事務が「算定に関係なし」か「医師に聞く」を、カルテと語の組で選ぶ（今の一覧の形。選ぶまで確かめ済みにしない）。一覧を開いたとき初期のチェックは、そのカルテだけ（C-662）
3. 医師への問いは、事務が「医師に聞く」を選んだものだけ（結び付けから自動で作らない）。引用は原文のその語を含む文。医師の答えは、その日のカルテの表示にだけ出す（記載の候補には戻さない。受け入れ条件 3 後半・5 を書き直す）
4. 選ぶ操作の監査の行をテストで縛る（ルートを通し、行を明示して足す。C-661）
5. 手間を抑えるのは固定の一覧だけ。算定に関係しない語（ADL など）を足すときは利用者の承認つき。止まる日の割合は、最初のクリニックの実物で測る

2. **辞書にある略語**（その日の原文の英字の語のうち、名称の語と固定の一覧を除き、辞書に出現形があるもの）：事務が辞書の候補（標準病名）から意味を選ぶ。候補には必ず「その他」「判定不能」。選んだ意味の語で、名称の決まった規則の候補を引く（LLM の lookup・推し量りは使わない）
3. **医師確認は必須**：事務が選んだ意味は、同じ月・同じ略語で患者をまたいで 1 問にまとめて医師に出す（事務の選んだ意味をカルテごとに並べ、医師が「このとおり」「違う（選び直す・その他・判定不能）」を答える）。医師が確かめるまで、その記載は確かめ済みにしない。答えは覚えない（毎回聞く）。辞書はクリニックの答えから育てない
4. **辞書にない略語**：そのカルテだけ、LLM の lookup と自動選択を止める（ほかのカルテ・ほかの日は止めない）。その略語は事務が「算定に関係なし」か「医師に聞く」を選ぶ（今の一覧の形・カルテと語の組）
5. **やめるもの**：字面で語と記載を結び付ける判定（作り直しの 3・補いの C-650）、言い換えの疑い
6. 受け入れ条件：辞書の取り込みの検査、AF（辞書の候補から選ぶ→医師確認→確かめ済み）、意味が割れる略語の候補、辞書にない略語でそのカルテだけ止まり別のカルテは止まらないこと、医師確認の 7 要件、round-96〜100 の例

## 辞書方式の決め（2026-11-25。承認済み：利用者「承認する」。利用者の判断：「事務が医師確認に必ず回すのはレベル４まで」「確認や月末の確認作業はそれで止めない」「違ったら辞書に書き足す」「一般的な略語を辞書に登録」。上の「辞書方式」の節を置き換える）
1. **辞書**：万病辞書 MANBYO（CC BY 4.0）を公開マスターと同じく手元で落として取り込み、略語の意味の**候補**に使う（一致しても正しいとはみなさない。sources/research/abbrev-dictionaries.md の測った結果）。出典を画面と README に表示。辞書にない一般的な略語（DOAC・HOT・NPPV・PEG・ADL など）は、出典のある公開データが見つかるまでは、医師の答えから書き足す（下の 5）。私が意味を作って登録しない
2. **事務が選ぶ**：辞書にある略語は、事務が候補（と「その他」「判定不能」）から意味を選ぶ。選んだ意味の語で、名称の決まった規則の候補を引く（LLM の lookup・推し量りは使わない）。候補が 1 つなら初期値にする
3. **医師確認**：事務のレベルが Lv.4 までなら、選んだ意味を必ず医師確認に回す（同じ月・同じ略語で患者をまたいで 1 問）。Lv.5 からは回すかを事務が選べる。医師確認の答えを待つあいだも、カルテの確かめと月末の点検は止めない（答えが来るまで「医師確認中」の札を出すだけ）
4. **辞書にない略語**：そのカルテだけ、LLM の lookup と自動選択（初期値）を止め、事務が名称の決まった規則の候補から選ぶ。その略語は事務が「算定に関係なし」か「医師に聞く」を選ぶ。どちらもカルテの確かめと月末の点検は止めない
5. **辞書に書き足す**：医師が「違う」と答えた意味や、辞書にない略語への医師の答えは、そのクリニックの辞書に書き足す（医師の答えなので承認済みとして足す。足した人・日・元の問いを残す。万病辞書の本体は書き換えない）。次からは候補に出る（2026-11-23 の「毎回聞く・覚えない」は、辞書への書き足しについては変える）
6. **やめるもの**：字面の結び付け・言い換えの疑い・「選ぶまで確かめ済みにしない」の関門
7. 受け入れ条件：辞書の取り込みの検査と出典の表示、AF（候補から選ぶ→Lv.4 は医師確認へ・Lv.5 は任意）、医師確認中でも確定と月末の点検が止まらない、辞書にない略語でそのカルテだけ自動選択が止まり別のカルテは止まらない、医師の「違う」で辞書に足され次から候補に出る、7 要件、Af と AF を分ける

## 医師確認の画面の文言（2026-11-25。利用者の依頼「被っている略語は使ってほしくない旨と、カルテをわかりやすく書くことが健全経営への第一歩、という文言を出して」）

  「カルテは、医療事務が読んで同じ意味にたどり着ける書き方だと、確認のお願いが減ります。意味が重なる略語（たとえば AF と Af）は避け、正式な名称で書いていただけると助かります。わかりやすいカルテが、クリニックの健全な経営への第一歩です。」

- 文言は config に 1 か所で持ち、禁止語の検査を通す
