## 機能ごとの作り方

- **F4 UKE**：記録条件仕様 令和6年6月版に沿って、IR/RE/HO/KO/SY/SI/IY/TO/CO/GO を読むパーサを自作する。合成 UKE は K1〜K6 の ClaimContext から生成し、パーサで読み戻して一致を確かめる（往復テスト）
- **F2 メンター**：Agent SDK のセッションを医療事務 1 人に 1 つ持たせる。システムプロンプトは「キャラ × レベル」で組み立てる。出力は構造化（本文＋`expression`＋引用した知識 id）。判定は必ず `EngineResult` を引用し、上書きしない。1 問の開始ごとに Skill の世代番号を比べ、変わっていればセッションを作り直す（design.md §5）。引用した知識 id は F5 に `USED` として渡す
- **F6**：`ask_peer_mentor` はベテランのメンターのセッションに問いを渡す。解けなければ `ask_human` でベテラン本人の画面に届く。解決したら F5 の `エスカレーション` イベントを発行する
- **F1/F3**：`ask_missing` の宛先で振り分ける。医師画面は質問・根拠（臨床指標）・選択肢・確認ボタン。未回答は翌営業日にリマインド、3 営業日で保留（営業日カレンダーは設定ファイル）
- **F7/F10**：1 問の流れ（ヒント→確定→判定→解説）を画面の状態機械にする。レベルは処理件数から決定的に計算し、メンターのプロンプトに渡す
- **F8**：ElevenLabs Agents（LLM＝Claude）を初回登録画面だけで使う。クライアントツールで「キャラ・呼び名」を API Route 経由で DB に書く
- **F9**：エンジンの Finding と修正前後の行を記録して集計する。本人向けは既定で非表示（トグル 1 つ）、事務長向けは月次
- **立ち絵**：Gemini で 1 キャラ 1 枚のシートを生成し、分割スクリプトで 6 表情に分ける
