### 4. 手間　14 / 20

よいところ
- 聞き取りの答えは患者ごとに残り、次の月にも効く（src/server/app/care.ts:149 のコメント）。同じ事実を点検側でまた聞かない（K4 の R03 で確かめた）。
- 短期入所の「使っていない」はまとめて残せる（app/uke/care-check/page.tsx:333-341）。

- 医師あての情報不足は、送る操作なしで医師の「確かめてほしい項目」に並ぶ（app/fact-input.tsx:203）。

引いた点
- **医師への「確かめてほしい項目」が答えにくい**：問いは「別表第八の二に当たるか」と請求の番号だけで、カルテの引用も、別表第八の二の状態の一覧もない（`GET /api/doctor/facts` の応答、src/messages.ts:307、app/doctor/fact-requests.tsx:73）。医師は制度の表の名前を知らないことが多く、事務へ聞き返しが来る。月末にここで止まる。

- **英語の普通の語も略語として印が付く**：「HR 72 irregular」の `irregular` が略語に並んだ（`POST /api/chart` の `abbrev.marks`）。拾い方が英字の並びだけ（src/chart/abbrev.ts:12）で、分かる語の一覧は 14 語（config/abbrev-known.json）。
- 1 か月目は、1 人につき 認定・住まい・短期入所・ほかの機関 の 4 問（`GET /api/uke/care-check?month=2026-10` の `asks`）。患者マスタで要介護 3 と分かっている K1 にも認定を聞く（fixtures/cases/K1.json:19-22、src/server/app.ts:315）。

## 100 点に届くための直しの順

1. 全件の一覧を、締めに使える数にする（#1〜#3）：患者情報の指摘を列に足す。カルテのない請求の項目は情報不足から「見ていません」に移す。聞き取りの未回答を「見ていません」の数に入れる。一覧の上に「残り n 件」を出す。
2. 医師への「確かめてほしい項目」に、カルテの該当の記載と、別表第八の二の状態の一覧（要旨）を添える（#4）。
3. 月末の入口を 1 つにする（#5）：月末は UKE の画面から始まると、入口とメニューで分かるようにする。算定画面の「月末の点検」は、摘要欄を見ないことを見出しで言うか、UKE の点検へ送る。
4. UKE の点検の画面から、その指摘についてメンターに聞けるようにする（#6）。
5. 略語の手間を減らす（#7・#8）：英語の普通の語を印から外す。新人でも、辞書の意味が 1 つで信頼度の高い語は医師へ回さずに済む道を作るか、回す数を画面に出す。
6. 見本の保険者番号を直し（#9）、課長が部下の進み具合を見られるようにし（#10）、患者情報の段階の読み方を README に書き（#11）、次のレセプトへのリンクを付ける（#13）。

- 見られなかったもの：実際の画面の描画と操作の感触（ボタンの位置・スクロール量）／実在用のクリニックでだけ出る「確かめ済み」の画面／30 人規模の月で聞き取りにかかる時間／ナレーションや声（ElevenLabs）／査定・返戻の突き合わせ（`/review`。今回の依頼の「試してよいもの」に入っていないので触らなかった）／算定画面の「月末の点検」で直して確定する一連（K5 で問題を作り、メンターに 1 回聞くところまで）。
