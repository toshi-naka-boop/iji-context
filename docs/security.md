# セキュリティとデータの扱い

レセメンはお試し用のプロダクトです。同梱のデータ（症例・見本の UKE・査定通知）は合成データだけですが、利用者が入れるデータは実在のものも受け取ります（設計書 §11-11）。
この文書は、入れたデータがどこへ行き、何が残り、何を消せるかをまとめたものです。

> このプロダクトはお試し用です。ご自身の責任において情報の授受をお願いします。

注意書きの本文は `config/notice.json` の 1 か所にあり、ログイン・UKE の取り込み・カルテを書く・通知の取り込みの各画面の入力欄の上に出ます。

## 脅威モデル（短く）

守るもの：利用者が入れた患者の情報（UKE、カルテの文と画像、査定・返戻の通知、確かめた患者情報、医師・ベテランへの問い）。

| 脅威 | 対策 | 残るもの |
|---|---|---|
| 利用者が知らないうちに、患者の情報が外部の AI・音声のサービスへ出る | 注意書きへの同意を先に取る。同意は、ルートの入口と、外部へ送る直前の 2 か所で確かめる | 同意した利用者が入れた内容は送られる（下の表） |
| 文脈を組み立てるコードの変更で、患者の識別子が AI に渡る | メンターに渡す請求は `claimForAi` を通した形だけ（請求 id・診療年月・過去月の算定）。目印の値を入れた請求で、送る文に現れないことをテストで確かめる | 自由記述・画像・通知の中の氏名と番号 |
| ほかのクリニックのデータが見える | クリニック（tenant）ごとに DB・ファイルの置き場を分ける。権限表でロールごとに操作を絞る | 同じクリニックの中では、ロールの範囲で互いに見える |
| ログ・監査ログから患者の情報が漏れる | ログは時間・件数・モデル名・エラーの種類だけ。監査ログは利用者 id・操作の名前・対象の id だけ | サーバーの管理者は DB とファイルを直接読める |
| サーバーのディスクを読まれる | 対策なし（保存時の暗号化はしていない） | 下の「残余リスク」 |

## 外部へ出るデータ

外部へ送る処理は 2 か所だけです：AI（Anthropic）は `src/llm/outbound.ts`、音声（ElevenLabs）は `src/voice/`。ほかのファイルからの SDK の読み込みは、テストがソースを走査して禁じています。

| 操作 | 送るもの | 行き先 | 識別子 |
|---|---|---|---|
| メンターに相談する（ヒント・解説） | 利用者が打ち込んだ文、ユスティの判定（ルール・行・指摘）、請求 id（アプリの番号）と診療年月、過去月の算定の区分、照合の不一致（病名・処方の分類）、本人の呼び名とレベル | Anthropic | 請求・患者マスタ・UKE から作る部分は外す。打ち込んだ文の中の氏名は外せない |
| メンターが医師確認・ベテランへの問いを作る | メンターが書いた質問と、利用者との会話 | Anthropic | 同上 |
| カルテを保存する（事実の読み取り） | カルテの 5 欄（S・O・A・P・処方）の文 | Anthropic | 外せない（自由記述） |
| カルテを SOAP に整える | 自由に書いた文 | Anthropic | 外せない（自由記述） |
| カルテの画像から取り込む | 画像そのもの（保存はしない） | Anthropic | 外せない（画像の中の氏名） |
| 代行入力の下書きを整える | 下書きの文 | Anthropic | 外せない（自由記述） |
| 査定・返戻の通知を読む | 通知の PDF そのもの | Anthropic | 外せない。氏名と番号を含めて送る（氏名と保険者番号で請求と対応づけるのが役目） |
| 声で名前を答える | 録音した声。漢字が混じっていれば、聞き取った名前の文字 | ElevenLabs、Anthropic | 利用者本人の名前（患者の情報ではない） |
| キャラの声を聞く | 決まった台詞と、本人の呼び名 | ElevenLabs | 同上 |

外す識別子：患者の氏名・生年月日（年齢は使ってよいが、いまは送っていない）・保険者番号・記号番号・公費の番号・医療機関コード・UKE のカルテ番号。
取り込んだ請求の id はアプリが振る番号（`U12-3` の形）で、UKE のカルテ番号は請求 id にも AI への文脈にも使いません。

UKE の中身（氏名・番号・診療行為）と患者マスタは、AI・音声のどちらにも送りません。連携（ORCA・FHIR）の接続先は環境変数の許可リストだけで、既定で無効です（`docs/connectors.md`）。

## 同意の仕組み

- 同意は利用者ごとに、注意書きの版（`config/notice.json` の `version`）ごとに 1 回。`users.accepted_notice_version`・`accepted_notice_at` に残し、監査ログにも残します。版を上げると、全員がもう一度聞かれます。
- **入口**：権限表（`src/server/policy.ts`）の全行が、`external`（外部へ送るか：`ai`・`voice`・`none`）と `patientData`（患者の情報を扱うか）を申告します（既定値はなし）。どちらかに当たるルートは、同意していない利用者には 403 を返し、画面は同意の画面を出します（`route()` が見るので、ハンドラごとには書きません）。
- **出口**：`outbound` と音声の関数は「誰の操作か」を受け取り、その利用者の同意を自分で DB で確かめます。入口の申告が漏れていても、同意のない利用者の入力は外に出ません（申告を全部 `none` に書き換えて確かめるテストがあります）。
- 利用者のいない呼び出し（種・評価のスクリプト）は `outboundForBundled` を使い、同梱の合成データだけを送ります。この入口は `app/` と `src/server/` から読み込めません。
- 知識の閲覧と提案には同意のゲートを置いていません（知識は、どのロールにも開く決まりのため）。知識の本文に患者の情報を書かない運用が要ります。
- 取り込んだファイルを消す操作は、同意を条件にしていません。

## 消せるもの・消せないもの

UKE の取り込み画面で、取り込んだファイルごとに消せます（事務長とベテラン。`DELETE /api/uke/uploads/[sha256]`）。請求ごとには消せません。

消えるもの：
- 原本のファイル、読み直しのキャッシュ、取り込みの記録
- そのファイルの請求にぶら下がる、提出・適用記録・提出結果・会議の項目・処理体験（問題）・医師確認・ベテランへの問い・訪問カルテ
- その請求を相談した人の、メンターとのやり取り（このサーバーに残るセッションの記録）と作業場所。やり取りは 1 人 1 つなので、ほかの請求の相談も一緒に消えます
- ほかのどの請求からも参照されなくなった患者マスタ・加入情報・確かめた患者情報（別のファイルに同じ患者の請求が残っていれば、患者は残ります）

残るもの：
- 監査ログ（消したファイルの内容のハッシュと、それまでの操作の対象の id）
- その請求から作った知識の候補（文は人が書いたもの。消すかは責任者が知識の画面で決めます）。知識の履歴には、提出の番号が残ることがあります
- AI・音声のサービス側に送った内容（こちらからは消せません）
- カルテを書く画面から入れた訪問カルテのうち、同梱の症例に書いたもの（消す操作はまだありません）

## 残余リスク

- **保存時の暗号化をしていません。** DB（SQLite）・取り込んだ UKE・医師確認の記録・メンターとのやり取りは、サーバーのディスクに平文で置かれます。
- **カルテの自由記述・画像・相談の文・通知の中の氏名と番号は外せません。** そのまま AI のサービスに送られます。
- **AI・音声のサービス側に送った内容は、こちらからは消せません。** 保持の期間と扱いは、各サービスの規約によります。
- **注意書きと同意は、法令上の義務をなくしません。** データを入れる人（医療機関）と運用する側には、個人情報保護法（要配慮個人情報）と、医療情報の安全管理のガイドラインの義務が残ります。公開版で実在のデータを受ける前に、運用する側の確認が要ります。
- 同意は「読んで押した」ことの記録で、患者本人の同意ではありません。
- 画面の応答（一覧・患者情報）には氏名が含まれます。ブラウザを共用の端末で開いたままにしないでください。
