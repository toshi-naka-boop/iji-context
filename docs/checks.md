# 月末の点検のくわしい説明

README の「月末の点検で何ができるか」の続きです。UKE の取り込みから、点検の結果が出るまでに、何を受け取り、何を見て、何を見ていないかをまとめます。
API と保存先のくわしいことは [connectors.md](connectors.md)、公開マスターの取り込みは [masters.md](masters.md)、消せるものは [security.md](security.md) にあります。

## 1. UKE の取り込み

画面は「UKE 取り込み」（`/uke`）です。月末にレセコンから書き出した提出用のファイル（UKE）を取り込むと、提出前に全件を決まった規則で点検します。デモのクリニックでは、見本の UKE をダウンロードして、そのままアップロードできます。

**受け取るもの**

- 見本と違う内容の UKE も受け取ります（同じ患者の別の月、国保連あて・支払基金あて など）。
- 読めるレコードは、記録条件仕様（医科用）令和8年8月版の、医科の請求ファイルに現れる 18 種です（医療機関情報 IR、レセプト共通 RE、保険者 HO、公費 KO、資格確認 SN、受診日等 JD、窓口負担額 MF、包括評価対象外理由 GR、傷病名 SY、診療行為 SI、医薬品 IY、特定器材 TO、コメント CO、症状詳記 SJ、臓器提供者のレセプト情報 TI・TR・TS、診療報酬請求書 GO）。
- 回数と 1 日の回数は仕様どおり 3 桁まで受け取るので、投薬の「処方した日に 14 日分・28 日分」の行も読めます。
- 資格確認・受診日等・窓口負担額・症状詳記は、読んで持つだけで、まだ点検には使っていません。

**断らずに残すもの**

- 対応していないコードの行（診療年月の版の表にない診療行為コード、医薬品・特定器材）があっても、ファイルは断りません。その行を含む算定の単位をまるごと「点検の対象外」として残します。
- 入院のレセプト、臓器提供者のレセプト情報を含むレセプト、上にないレコード（DPC のレコードなど）を含むレセプトは、ファイルを断らずに、そのレセプトだけを「いまは点検できない」と出します。

**断るもの**

- 形式が違う、対応しているコードの点数が点数表と合わない、合計が合わないファイルは、行番号つきで断ります。
- 同じファイルの取り込み直しも断ります。

取り込んだレセプトには、アプリが請求の番号（`U1-1` の形）を振ります。UKE のカルテ番号は、患者の番号として表示にだけ使います。取り込んだファイルは、事務長・ベテランが画面から消せます（消えるもの・残るものは [security.md](security.md)）。

## 2. 診療年月に当たる版がないとき（試算）

点数とルールは改定の版に属し、診療年月から版を 1 つに決めます。改定前の診療年月など、当たる版がないレセプトも断りません。

- 一覧に「この診療年月の版はありません（試算できます）」と出し、月末の点検と提出には並べません。
- 開くと、版を選んで試算できます。選んだ版の点数表とルールで読み、UKE に書いてある点数とその版の点数の違いを並べます。
- 画面の上に「実際の請求の判定ではありません」と出し、結果は保存しません。
- 版のあるレセプトも、版を替えれば同じように試算できます。選べるのは診療行為コードの表を持つ版だけで、令和6年度の版（改定の比較用）は選べません。

## 3. 取り込んだレセプトの点検

取り込み画面の一覧から 1 件ずつ開くと、UKE に書いてあるとおりのまま点検した結果が出ます（行もコメントも入れ替えません）。

- **合計は 2 つ**：UKE に書いてある請求の合計と、点検した行の小計です。対象外の行があるレセプトでは「対象外の行が n 行あります」と必ず出し、小計を請求の合計として見せません。
- **対象外の行があるとき**：ほかの行の有無や回数で決まる点は、言い切れなくなります。手書きのルールは、対象外の行があっても言える指摘の種類をルールごとに申告していて（`soundWhenPartial`）、それだけを出し、ほかは「決められません」と出します。公開マスターが入っていると、対象外の行の区分番号を見て、同じ区分番号の行を読むルールだけを止めます（例：尿検査の判断料が対象外にあっても、「訪問診療料のない月の管理料」は指摘します）。
- **カルテ側の記録がない**：取り込んだレセプトは、カルテ側の事実（要介護度・訪問の記録など）がないまま月末の点検に並びます。足りない事実は「情報不足」として出し、推し量って埋めません。
- **点検の範囲**：動いた点検、動かなかった点検とその理由を、必ず画面に出します。「指摘はありません」は、動いた点検についてだけ言います。

## 4. 点検の前の聞き取り（介護保険・ほかの医療機関）

画面は「点検の前に確かめること」（`/uke/care-check`。UKE 取り込みの画面から入ります）です。

- 介護保険との調整（R20）と、ほかの医療機関・訪問看護との調整（R21）に要る事実を、患者ごとに確かめて残します。聞くのは、住まいの種別・短期入所を使ったか・要介護や要支援の認定・ほかに関わる機関など、判定に要るものだけです。
- 答えは、開いた UKE の診療年月の分として残り、点検は決まった規則で計算し直します。答えには出どころ（被保険者証・ケアマネジャーからの連絡など）を付けます。
- 月ごとに「確かめる患者」と「見ていない患者」の数が出ます。答えがないあいだ、その患者の点検の範囲には「見ていません」と出ます（空のまま「問題なし」とは言いません）。
- 当院からはほかの機関の請求が見えないので、R20・R21 の指摘はすべて条件つき（「申告のとおりなら」で始まる文）です。

## 5. 手書きのルール（R01〜R21）

ユスティ（`src/engine/rules/`）が持つ、決まった規則のルールです。どれも令和8年度改定後の版で動き、公開マスターがなくても動きます。

| ルール | 見ること |
|---|---|
| R01 | 在医総管の区分は同じ月の訪問診療の回数で決まる。訪問診療のない月は算定できない |
| R02 | 別表第八の二に当たる患者は重症の区分で算定する。重症の区分の月に包括的支援加算は付けない |
| R03 | 包括的支援加算は、別表第八の三の状態（要介護 3 以上など）の患者に付ける |
| R04 | 在宅療養指導管理料は主たるもの 1 つ。材料加算はそれぞれ算定できる |
| R05 | 在医総管の月は、所定点数に含まれる項目を別に算定しない |
| R06 | 特定疾患処方管理加算は、主病が対象の疾患のとき |
| R07 | 処方箋料は、内服 7 種類以上で別の区分 |
| R08 | ベースアップ評価料(Ⅰ) は、訪問診療の日と往診だけの日で区分が違う |
| R09 | 死亡診断加算と看取り加算は併せて算定しない。在宅ターミナルケア加算の訪問の要件 |
| R10 | 緊急往診加算の対象、同じ日・翌日の往診と訪問診療 |
| R11 | 検体検査判断料は区分ごとに月 1 回 |
| R12 | 在宅医療DX情報活用加算と、併せて算定しない加算 |
| R13 | 週 3 回を超える訪問診療は、別表第七の疾病等か急性増悪のときに限る |
| R14 | 在宅移行早期加算の対象と期間 |
| R15 | 物価対応料は、訪問診療の日と往診だけの日で区分が違う（R08 と同じ規則） |
| R16 | 管理料は、居宅の患者は在宅時医学総合管理料、施設に入居している患者は施設入居時等医学総合管理料。居住の場所で決まる |
| R17 | 摘要欄の記載（必ず要る記載のもれと形式、日付の突き合わせ） |
| R18 | 施設の種別で分かれる区分と、施設の申告が合っているか |
| R19 | 単一建物の人数の区分と、確かめた人数が合っているか |
| R20 | 介護保険との調整（聞き取りの申告のとおりなら算定できない行。条件つき） |
| R21 | ほかの医療機関との調整（聞き取りの申告のとおりなら算定できない行。条件つき） |

ルールごとの説明は `.claude/skills/iji-system-r01`〜`r21` にあり、メンターも同じ文を読みます。

## 6. データで動く点検（G01〜G12）

公開マスター（厚生労働省の基本マスター、審査支払機関の電子点数表・コメント関連テーブル・チェックマスタ）を手元で取り込むと動く点検です（`src/generic/`）。データは同梱していません。取り込み方は [masters.md](masters.md) です。マスターがなければ、どれも動かず、点検の範囲に「マスターが入っていないので、していません」と出ます。

指摘は、ほとんどが「条件つき」です。言い切り（確定）にする指摘の種類は `config/generic-checks.json` の `certain` に 1 行ずつ足し、足す前に表の行を告示・通知の原文と突き合わせます。手書きのルールが同じことを言っているときは、データの側からは出しません（2 回言わない。`src/generic/overlap.ts`）。

| 点検 | 見ること |
|---|---|
| G01 コード | 持っているどの版のマスターにもないコード、診療年月の前後どちらかの版にしかないコード |
| G02 点数の検算 | 算定の単位ごとに 1 回分の点数をマスターから計算し直し、UKE の点数と合わないもの |
| G03 行の属性 | 入院専用のコード、年齢の範囲の外、病院・診療所の別 |
| G04 包括・G05 背反・G06 算定回数 | 電子点数表に載っている組・上限と、レセプトの単位・算定日・回数 |
| G07 必須コメント | 算定すれば必ず要る記載のコメントコードが、レセプトのどこにもない行為 |
| G08 傷病名の要件 | 対象の傷病名が要る行為に、対象の傷病名コードが 1 つもないレセプト |
| G09 適応・併用 | 審査支払機関のチェックマスタの対象に当たるもの（ほかと分けた見出しの下に、折りたたんで出す） |
| G10 施設基準 | 請求の行が要る施設基準を、施設の申告が持っているか |
| G11 取り忘れ | カルテにあって請求にない行為 |
| G12 酸素 | 在宅酸素療法の月の酸素の行、上限を超えた単価、届け出た単価との違い |

### G01〜G09

- **名称**：全部の行（点検の対象外の行・医薬品・特定器材も）に名称と区分番号が付き、コメントコードと傷病名コードにも名称が付きます。
- **G01**：言い切りません。打ち間違いか、マスターの更新もれかを確かめるためのものです。
- **G02・G03**：％加算・％減算のある単位、購入価格の器材、表を持っていない包括の検査などは検算せず、その数と理由を出します（合っているとは数えません）。注加算の付け先・実日数・診療識別・後期高齢者医療の区分は点検していません。
- **G04〜G06**：表の特例条件が「条件あり」の行、同時に行ったかがレセプトから決まらない組、週の上限は、言い切りません。
- **G07**：見るのは「あるか・ないか」だけで、中身は見ません。条件が文章で書かれた記載（条件区分 00）は、指摘の数に入れず、点検の範囲に「記載が要ることがある項目 n 件（判定していません）」と畳んで出します。
- **G08**：特定疾患療養管理料・特定疾患処方管理加算・てんかん指導料・皮膚科特定疾患指導管理料が対象です。未コード化の傷病名があるレセプトでは言いません。難病外来指導管理料は点検していません。
- **G09**：全部「条件つき」で、言い切りには上げません。公開元が、コンピュータチェックは診療内容の適否を一律に決めるものではなく、症例ごとに審査委員会が判断すると断っているためで、指摘が出ても、査定されると決まったわけではありません。表に載っていない薬・診療行為には何も言いません（「問題なし」とも言いません）。院外処方の薬は医科のレセプトに載らないので見られません。量と日数（最大投与量・最長投与日数）、傷病名との禁忌は点検していません。

### G02 の包括の検査（表の三段）

検体検査をまとめて算定する表（版の表にある群。今は D007・D008・D013）は、項目数から表の値で検算します。ただ、同じ日の 2 回目以降の採血か、どの検体かは UKE に書かれていません。そこで、確定を置かずに三段で見ます（`src/generic/points.ts`）。

1. 表の値に合う：合っているとして数えます。
2. 同じ日の 2 回目以降の採血の項目（D013 は血液でない検体の項目も）を表の外と読んだ値に合う：条件つきで「こう読めば合う」と出します。
3. どれとも合わない：条件つきで出します。

画像診断の撮影部位は、コメントコードと記入値（左右など）の組を、許した一覧で数えます。D009 と特異的 IgE の上限、購入価格の器材は、まだ表を持っていません（検算の範囲にそう出します）。

### G10 施設基準

- 請求の行ごとに、医科診療行為マスターの施設基準の組を読み、施設の申告（「設定」の画面の「施設の申告」）で「持つ・持たない・分からない」を決めます。
- 申告が「分からない」、または確かめ直す日を過ぎているときは、その施設基準に依る判定を「問題なし」と言いません。
- 指摘には「施設の申告による」と添えます。人員・実績などの要件を実際に満たしているかは確かめません。
- 在医総管・施医総管の注14（単一建物 10 人以上の区分）は、届出の有無ではなく、通常の点数と減算の点数のどちらで算定しているかの申告で見ます。当たるかを数える計算の道具もあります。

### G11 取り忘れ

- 本人が確かめたカルテの「行ったこと」と請求を突き合わせ、カルテにあって請求にないものを「カルテにあるが請求にない（条件つき）」の欄に出します。
- AI が担うのは、カルテから書いてあることを取り出すところまでです。マスターへの当てはめは、名称の一致と本人の選択だけで決めます。当てられない行為は「当てられない」と出し、黙って捨てません。
- 包括・背反・回数（G03〜G06）と施設基準（G10）で算定できないと決まるものは出しません。候補どうしの包括・背反や、手書きのルールが関わる候補は、隠さずに添え書きをつけて出します。
- 電子カルテの構造化データ（訪問の時刻・処方のオーダー・在宅療養の機器）があれば、調剤料・処方料・処方箋料・患家診療時間加算・材料加算などを決まった規則で出し、請求になければ候補にします。項目が取れない場面は「見ていません」と出します。
- 記録にない算定を促すものではありません。点数・金額は出しません。指摘がないことを「取り忘れなし」とは言いません。

### G12 酸素

- 酸素の行（特定器材で酸素のコード）について、在宅酸素療法指導管理料の月に算定しない酸素、告示の上限を超えた単価、離島等のコード、クリニックが届け出た単価との違いを見ます。
- 届け出た単価は任意で、「設定」の画面の「酸素の単価」に入れます。単価は施設の値で、制度の採用値ではありません。離島等には当たらない前提で見ます。
- 酸素吸入の行と重なる点は G05 に任せ、2 回言いません。

## 7. 数を見る

マスターを入れた環境で、取り込んだ UKE に対する点検の数を見られます（患者の氏名・番号は出しません）。

```bash
RESEMEN_MASTER_DIR=<データ置き場>/masters npx tsx scripts/measure-generic.ts <UKE のファイル…>
```

どれも患者は合成です。作り方は `scripts/gen-uke.ts`・`scripts/gen-care-uke.ts`、症例は採用値の表（EM 5-1）にあるものだけです。

| `fixtures/uke/kisaimore.UKE` | 摘要欄の必須の記載を 1 つ欠いた |
