# 公開データ（マスター）の取り込み

全部の行の点検（設計書 §12）は、公開されている機械可読のデータを読んで動きます。この文書は、そのデータの一覧・利用条件・取り込みの手順・確かめ方をまとめたものです。
データで動く点検は、G01（コード）、G02（点数の検算）・G03（行の属性）、G04（包括）・G05（背反）・G06（算定回数）、G07（必須コメント）・G08（傷病名の要件）、G09（適応・併用）の全部が入っています。手書きのルール（R01〜R18）は、データがなくても今までどおり動きます。

## マスターを入れると見えるようになること

取り込んだレセプトの点検（UKE 取り込みの一覧から開く画面）で、次が変わります。マスターがなければ、どれも今までどおりです（コードだけを出し、点検の範囲に「マスターが入っていないので、していません」と出します）。

- **全部の行の名称**：点検の対象外の行（版の表にないコード・医薬品・特定器材）にも、診療年月に使う 1 枚のマスターの名称が付きます。診療行為には区分番号（例 `C001`、`D026`）も付きます。コメントコードにはコメントマスターの定型文、傷病名コードには傷病名マスターの名称が付きます。マスターにないコードは、コードだけを出します
- **コードの点検（G01）**：持っているどの 1 枚にもないコードは「持っているどの版のマスターにもありません。打ち間違いか、マスターの更新もれを確かめてください」、診療年月の前後どちらかの 1 枚にしかないコードは「前（後）の版にだけあります」と出します。どちらも「条件つき」で、言い切りません（持っている 1 枚のあいだの更新を、全部持っているとは確かめられないため）。マスターの変更年月日は、使い始めの日として使いません（経過措置の期限を付けただけでも変わるため）。月末の点検（行を入力する画面）と、カルテの算定の見込みにも、区分をコードに直して同じ点検を掛けます
- **点数の検算（G02）と行の属性（G03）**：算定の単位（点数を書く行までのまとまり）ごとに、1 回分の点数を医科診療行為・医薬品・特定器材マスターから計算し直し、UKE の点数と合わない単位を「条件つき」で出します（診療行為の点数の合算・きざみ、薬剤料、特定器材料、生化学的検査(Ⅰ) の項目数）。計算し直せない単位（％加算・％減算、購入価格の器材、項目数の表を持っていない包括の検査、コメントの値で計算する単位など）は「検算の対象外」として数と理由を出し、合っているとは数えません。行の属性は、入院専用のコード、年齢の範囲（数字で決まるもの）の外、病院・診療所の別の 3 つだけで、注加算の付け先・実日数を超える回数・診療識別・後期高齢者医療の区分は点検していません。施設基準のある行には、指摘ではなく「届出が要ります」と添えます。式を確かめた原文の計算例は、EM §2-11 の「式の錨」にあり、`masters:build` が毎回確かめます
- **包括・背反・算定回数の点検（G04・G05・G06）**：電子点数表（補助マスター・包括・背反の 4 表・算定回数）に載っている組・上限を、レセプトの単位・算定日・回数と突き合わせます。包括は、親の行為の単位（同じ日・同じ月）の中に、含まれる行為が別にあるとき。背反は、表の単位（1 日・同じ月・同時・1 週間）の中に、組の両方があるとき。算定回数は、日・月・週の上限を超えるとき。どれも「条件つき」で出します（言い切りは、種類ごとに確かめてから一覧に足します）。表の特例条件が「条件あり」の行、同時に行ったかがレセプトから決まらない組、週の上限は、一覧に足しても言い切りません。点検していないこと（手術前 1 週間の包括、2 月以上・一連・入院中などの上限）は、点検の範囲に出します。出どころは、表の名前と行の鍵です
- **必須コメントの点検（G07）**：コメント関連テーブルで、レセプトにある診療行為・医薬品・特定器材のコードごとに、算定すれば必ず要る記載を引き、そのコメントコードがレセプトのどこにもなければ「摘要欄に〈定型文〉の記載が見当たりません」と「条件つき」で出します（定型文はコメントマスターの名称。置き場所は見ません）。使うのは、条件区分が「その行為の算定が条件で、ほかの条件がない」行と、入院外のレセプトでの「入院外で算定した場合」の行で、記載要領の別表Ⅰ（医科）・別表Ⅱ（医薬品）・別表Ⅳ（特定器材）の行です。条件が記載要領の文章にある行、複数回算定したときの行、DPC・選定療養の行、診療年月の後に変わった行は使いません。同じ項番・枝番にコメントコードが複数ある組は、選択（どれか 1 つ）か全部要るかが表から決まらないので、1 つもないときだけ出します（どれか 1 つがあれば言いません）。見た組の数・複数ある組の数・点検していない組の数は、点検の範囲に出します。見るのは「あるか・ないか」だけで、日付・数値・文章の中身は見ません（在宅の 8 項目の中身の突き合わせは、手書きの R17 がします）
- **傷病名の要件の点検（G08）**：対象の傷病名が要る診療行為（医科診療行為マスターの傷病名関連区分：特定疾患療養管理料・特定疾患処方管理加算、てんかん指導料、皮膚科特定疾患指導管理料(Ⅰ)(Ⅱ)）がレセプトにあり、傷病名マスターでその対象とされている傷病名コードが、レセプトの傷病名に 1 つもないとき、「条件つき」で出します（言い切りには上げません）。未コード化の傷病名（0000999）や、持っているマスターにない傷病名コードがあるレセプトでは言いません（名称では当てません）。疑い病名・転帰のある傷病名も、対象の傷病名として数えます（指摘を出さない側）。主病かどうかは見ません。難病外来指導管理料は点検していません（傷病名マスターの区分が、告示の対象を覆っていると確かめられないため）。傷病名を持たない行（月末の点検・算定の見込み）には掛けません
- **適応・併用の点検（G09）**：審査支払機関が公開しているチェックマスタ（コンピュータチェック対象事例の表）で、次の 3 つを見ます。全部「条件つき」で、言い切りには上げません（言い切りの文を持ちません）
  - 適応（医薬品）：院内で使った薬（レセプトの医薬品の行）のうち、医薬品適応関連マスタに傷病名の行がある薬で、表の傷病名コードのどれも、レセプトの傷病名にないもの。「〈薬〉：レセプトの傷病名に、審査支払機関のチェック用の表にある傷病名が見当たりません（表の傷病名は n 件：先頭の 3 件 ほか）。傷病名のもれか、表にない使い方かを確かめてください」と出します。同じ薬が複数の日・複数の単位にあっても、薬ごとに 1 件です
  - 適応（診療行為）：医科診療行為傷病名関連マスタに行がある診療行為（検査・処置・手術・管理料など 1,602 種）で、同じ見方をします。表が確定病名だけを対象にしている行では、疑い病名（修飾語「の疑い」）は当たりに数えず、「疑い病名としてだけあります」と出します。傷病名の要件（G08）と同じ行為に重なるときは、G08 だけを出します
  - 併用：医薬品併用禁忌関連マスタにある組が、同じ算定日に両方あるもの。この表には、併用禁忌のほかに、併用注意などの組も入っていて、どれに当たるかは表から分からないので、「併用のチェック用の表にある組」とだけ言います
  - **但し書き**：公開元は、コンピュータチェックは診療内容の適否を一律に決めるものではなく、症例ごとに審査委員会が医学的に判断する、と断っています。ここに出るのは「チェックの対象に当たる」ことだけで、査定されると決まったわけではありません。表の傷病名は、公開元がチェック用に選んだもので、添付文書の効能・効果そのものではありません。画面では、ほかの点検と分けた見出し「審査支払機関のコンピュータチェックの対象（適応・併用）」の下に、折りたたんで出します。見出しには「投与量・投与日数は点検していません」を添えます（折りたたんだままでも見えるように）
  - **言わないこと**：表に載っていない薬・診療行為（チェックの対象外です。「問題なし」とも言わず、「適応の表にある薬 n／レセプトの薬 m」を点検の範囲に出します）。未コード化の傷病名（0000999）や、持っているマスターにない傷病名コードがあるレセプトの適応（名称では当てません）。傷病名を持たない行（月末の点検・算定の見込み）
  - **見られないもの・していないこと**：院外処方の薬（医科のレセプトに薬が載りません。処方箋料のあるレセプトでは、そのことを点検の範囲に出します）。量と日数（表の最大投与量・最長投与日数は、単位と、1 日あたりかどうか・どの期間の日数かが仕様書に書かれていないので、使っていません）。傷病名との禁忌、同じ成分の薬をまとめた量、過去の月にまたがる日数（要る表を取り込んでいません）。性別・年齢の条件の読み分け（表に性別・年齢の条件つきの行が 1 つでもある薬・診療行為は、適応を見ません。確かめた版で、薬 580 種・診療行為 96 種。その数を点検の範囲に出します）。同じ成分の別の銘柄は、まとめずに薬ごとに出します
  - **数え方**：傷病名は 7 桁のコードの一致で、修飾語は見ません。薬では、疑い病名も当たりに数えます。転帰（治ゆ・中止など）のある傷病名も数えます（どれも、指摘を出さない側）
  - **いまの版**：2026年10月30日公開の 1 枚で、2026年10月診療分にそのまま使います。公開元は、令和8年度診療報酬改定に伴う新しい事例の公開は次回以降としているので、改定で変わった取扱いは、まだ入っていないことがあります（点検の範囲に出します）
- **手書きのルールとの重なり**：手書きのルール（R04・R05・R09・R11・R12）が同じ組を指摘しているときは、データの側からは出しません（2 回言わない）。必須コメントは R17 と、同じ記載（コメントコード）について重ねます。傷病名の要件は R06（特定疾患処方管理加算）と重ね、R06 が主病を確かめて黙った請求には出しません（「手書きのルールが判定済み」に数えます）。手書きのルールが「確かめてください」で止まったときは、データの側から出します（届出の区分が不明でも、併算定できない 2 つが両方あることは言えます）。出さなかった数は、点検の範囲に出します
- **対象外の行があるときに止めるルールが、ルールごとになります**：マスターがないときは、対象外の行が 1 行でもあれば、ほかの行の有無や回数で決まる指摘をどのルールでも止めます。マスターがあると、対象外の行のコードの区分番号（医科診療行為マスターのコード表用番号の章・部・区分番号）を見て、そのルールが読む行と同じ区分番号のコードがあるとき（と、マスターにないコードがあるとき）だけ、そのルールを止めます。画面には、止めたルールと、そうさせた行を出します。合計の出し方は変わりません（対象外の行があれば、点検した行の小計と UKE の合計を分けて出します）
- **点検の範囲**：動いた点検、データがなくて動かなかった点検、準備（錨）ができていない点検を、点検ごとに出します。「指摘はありません」は、動いた点検についてだけ言います。適応・併用（G09）の但し書きと、見たもの・見られないものは、G09 の見出しの下に出します

言い切り（確定）で出す指摘の種類は `config/generic-checks.json` の `certain` に 1 行ずつ足します。いまは 4 種類（入院に限るコード・診療所に限るコード〔施設が病院のとき〕・同じ算定単位で併せて算定できない組・1 日の回数の上限）で、ほかはどれも条件つきです。足す前に、表の行を 30 行取って告示・通知の原文と突き合わせ、結果を利用者に報告します（`design/iji-context/sources/research/certain-sample.md`）。

数を見るには（患者の氏名・番号は出しません）：

```bash
RESEMEN_MASTER_DIR=<データ置き場>/masters npx tsx scripts/measure-generic.ts <UKE のファイル…>
```

レセプトごと・合計で、識別できた行の割合（マスターで名前が付いた行／全部の行）、対象外の行があるために止まったルールの割合（マスターがないときの止め方との比較）、点検ごとの指摘の数（確定・条件つき）を出します。適応・併用（G09）は、種類ごとの指摘の数、適応の表にある薬・診療行為の割合、レセプト 1 件あたりの指摘の数（平均・最大）も出します。

## 利用条件（同梱しない理由）

- どのデータも、**このリポジトリにも配布物にも入れていません**。再配布してよいかが、どの公開元にも明記されていないためです。審査支払機関のサイトは「無断使用・転載を禁止」としています（ https://www.hpdx.or.jp/riyo.html ）
- 使う人が、自分の手元に公開元から落として読み込みます。点検に使うこと自体は、電子点数表の手引きが書いている公表の目的（医事会計システム等でのチェック）に沿うと読んでいます
- いまの用途は**社内のテスト**です。配る製品にするとき・データを同梱するときは、先に公開元へ確認が要ります（未確認）
- 落としたファイルと `masters.db` は、データ置き場（`RESEMEN_DATA`。既定は `./data`）の下に置きます。git には入れません（`.gitignore` で `data/masters/` を外してあります。別の場所をデータ置き場にしたときも、リポジトリの中に置かないでください）

## 取り込みの手順

```bash
npm run masters:fetch              # 何をどこから落とすかの一覧だけを出す（落とさない）
npm run masters:fetch -- --yes     # 落として <データ置き場>/masters/raw/ に置く
npm run masters:fetch -- --yes tensuhyo checkmaster   # データ名を書けば、その分だけ
npm run masters:build              # raw/ から <データ置き場>/masters/masters.db を作る
npm run check:masters              # 今ある masters.db を確かめ直す（なければ飛ばす）
```

- `masters:fetch` は、`--yes` が付いていなければ落としません。接続するのは `config/masters.json` に書いてあるホスト（`shinryohoshu.mhlw.go.jp`・`www.hpdx.or.jp`）だけで、https、リダイレクトには従わず、時間と大きさに上限があります。zip は `unzip` コマンドで中の名前と大きさを確かめてから、要るファイルの中身だけを取り出します（`unzip` が要ります）。すでにあるファイルは上書きしません
- 公開元が置いているのは、どのデータも「いまの 1 枚」です。過去の更新分は落とせません（チェックマスタだけ過去の版がありますが、令和8年度改定より前のものなので落としません）。**更新のたびに落として、1 枚ずつ貯めてください**
- `masters:build` は、`raw/` にある更新日の 1 枚を全部取り込みます（毎回、全部を作り直します。8 秒ほど、190MB ほど）。作りかけは別のファイルに書き、検査が全部通ってから置き換えます。失敗したときは、今ある `masters.db` には触りません
- アプリは `masters.db` を読み取り専用で開きます。なければ「入っていません」と出すだけで、動きは変わりません。状態は、事務長の「設定」の画面の「マスターの状態」で見られます

公開ページから手で落として、次の形に置いても同じです。更新日は 8 桁の数字のフォルダにします（ファイル名に日付があるものはその日付、電子点数表は公開ページの【令和 n 年 m 月 d 日】）。

## 取り込みのときに確かめること

1. **形式**：Shift_JIS として読めるか、1 行の項目数、見出しの行（チェックマスタ）、取り込む項目の型と値の区分（コードの桁、点数は数、年月日は 8 桁、区分は仕様書に挙がっている値）。1 行でも合わないファイルは取り込まず、理由を出します（別の版のレイアウトを黙って読みません）。件数 0 も取り込みません
2. **錨**：原文（告示・通知・記載要領・手引き・仕様書の記載例）で確かめた、データの中の具体的な事実です（例：在宅時医学総合管理料の包括のグループに処方箋料がある／往診料と訪問診療料は同じ日にはいずれか 1 つで、条件がある／血液学的検査判断料は月 1 回）。採用値のファイル §2-11 の表 2 にあり、持っている 1 枚ごとに全部成り立つことを確かめます。**1 つでも外れたら失敗**です。列を 1 つ読み違えると、どれかの錨が外れます
3. **値ごとの件数**：判定に使う列の、値ごとの件数（§2-11 の表 3）。読み方を確かめた版と同じ 1 枚では一致しなければ失敗、ほかの 1 枚では 1 割を超えて違えば警告です
4. **版の表との食い違い**：アプリが持つ版の表（点数・コード。`src/engine/revisions/`）と、医科診療行為マスターの 1 枚が食い違えば、全部出して失敗にします。どちらかを黙って優先しません
5. **点検の準備**：点検 G01〜G09 ごとに、要る表がそろい、判定に使う列の値に錨があるかを `masters.db` の `checks_ready` に残します。錨のない列を使う点検は動かしません

## 更新のしかた

- 公開元が更新したら、`masters:fetch -- --yes` → `masters:build`。古い 1 枚は消さずに残します（レセプトの診療年月の末日以前で、いちばん新しい 1 枚を使うため）
- 読み方を確かめた版（§2-11 の表 1）より新しい 1 枚が入ると、警告と、設定の画面の「確かめた版より新しい」が出ます。止まりはしません。形式・錨の検査が通っていれば読めていますが、件数が大きく変わったときは、公開元の更新内容を見てから、§2-11 の確かめた版と件数を直します
- 形式の検査や錨で失敗したときは、検査を緩めたり錨を消したりせず、仕様書と原文に当たって、読み方（`src/masters/layout.ts`）か採用値のファイルのどちらが違うのかを確かめます
- 改定で世代が変わるとき（令和 10 年度）は、`config/masters.json` の世代と、仕様書の新しい版でのレイアウトの確認が要ります。違う世代の 1 枚を同じフォルダに置かないでください
- 世代を替えて `masters:build` すると、今ある `masters.db` から、前の世代のデータごとのいちばん新しい 1 枚を写して残します（背反の組の院内の知識の、改定の前後の比べに使います。design.md §14-4）。錨・件数の検査は、いまの世代の 1 枚にだけ掛けます。前の `masters.db` を消してから作り直すと、前の世代の 1 枚は残りません

## テスト

データのない環境（CI）では、数行の手作りの表で動くテストだけが動きます。実データで確かめるテストは、`masters.db` のあるフォルダを環境変数で渡したときだけ動き、ないときは「飛ばした」と表示します。

```bash
RESEMEN_MASTER_DIR=<データ置き場>/masters npm test
```
